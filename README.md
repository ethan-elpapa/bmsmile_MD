# 글로벌 온라인 플랫폼팀 KPI 보드

이번 달 목표가 어디까지 왔는지, 프로젝트가 어디쯤 가고 있는지, 팀원 각자가 뭘 붙잡고 있는지를
한 장에서 보는 보드. Next.js(App Router) + Vercel, 데이터는 Redis 한 칸에 JSON 으로 들어간다.

**구조는 국가 확장 진행판(`../expansion-board`)과 같다** — 저장 방식, 편집 키, 20초 동기화,
`rev` 낙관적 잠금까지 그대로다. 두 보드를 오갈 때 운영 방법을 새로 배우지 않아도 되게 맞췄다.
매출 대시보드(`../amz-us-board`)와는 성격이 다르다. 저기는 구글 시트에서 읽어 온 숫자를 보여 주고,
여기는 사람이 채우는 목표·업무가 중심이고, 매출·광고 실적만 같은 시트에서 읽어 온다.

## 다섯 덩어리

| 섹션 | 무엇 | 누가 채우나 |
|---|---|---|
| **월 목표** | 브랜드 × 마켓 × 채널별 매출·ROAS·광고비 목표와 실적 | 월초에 목표, 주기적으로 실적 |
| **프로젝트** | 언젠가 끝나는 덩어리 (담당·기한·상태) | 시작할 때 한 번, 상태는 수시로 |
| **팀원** | 누가 무엇을 붙잡고 있는지 (읽기 전용) | 아무도 — 업무에서 계산된다 |
| **주간** | 주차마다 팀원 각자가 적는 항목들 · 컨펌 요청 | 각자 자기 줄, 컨펌은 팀장 |
| **업무** | 누가 무엇을 언제까지 | 배정할 때, 그리고 각자 상태 변경 |

업무는 사람과 프로젝트 **양쪽에 붙는다.** 그래서 프로젝트 진행률(3/7)이 업무 목록에서 자동으로 나온다.
따로 세는 곳은 없다. 주간의 업무 건수도 마찬가지 — 업무의 **기한이 그 주에 들면** 저절로 세어진다.

## 실적은 시트에서 온다

채널 줄의 **실적**은 매출 시트에서 읽어 온다. 목표는 사람이 넣는다.

```
브라우저  ──GET /api/feed?month=2026-09──▶  lib/feed.ts
                                             │
                                             └─▶ docs.google.com/…/export?format=csv&gid=0
                                                 일별 행을 그 달로 합산
```

**서비스 계정을 쓰지 않는다.** 시트가 '링크가 있는 사람은 보기' 로 열려 있어서 CSV 내보내기 주소를
그냥 부르면 된다 — 자격증명도 패키지도 필요 없다. 공유를 조이면 이 길이 막히고, 그때는
`../amz-us-board/lib/sheets.ts` 의 서비스 계정(JWT) 방식을 가져오면 된다. **그 시트는 이미 그 계정에
공유돼 있다** — 같은 문서다.

| 보드 지표 | 시트 열 (일별 롤업 탭) |
|---|---|
| 총매출 | 매출 ($) |
| 내부 광고비 | AMZ 광고비 ($) |
| 외부 광고비 | MATA 광고비 ($) |
| 총 ROAS | 매출 ÷ (AMZ + MATA) |

- **읽은 값은 보드에 저장하지 않는다.** 화면에 얹기만 한다 — 저장하면 시트를 고쳐도 보드만 옛날
  값으로 남고, 두 곳이 같은 칸을 쓰는 꼴이 된다
- **시트에 그 달 값이 없으면 저장된 값으로 물러나고 칸도 다시 열린다.** 연결됐다는 이유로 아무도
  못 고치는 빈 칸이 남지 않게. 시트를 못 읽어도 마찬가지다(채널 이름 밑에 `시트 못 읽음` 이 뜬다)
- **채널 이름 밑의 `시트 9/5까지` 가 반영 범위**다. 시트가 하루 이틀 늦게 채워지기 때문에
  이 표시가 없으면 "9월 매출이 왜 이렇게 적지" 를 매번 다시 확인하게 된다
- 열 위치는 `lib/feed.ts` 의 `COL` 에 있다. **이름이 아니라 자리로 찾는다** — 이 탭은 머리글이 두
  줄에 걸쳐 있고 병합된 칸이 많아 이름으로 잡는 쪽이 더 잘 깨진다. 시트 열 순서를 바꾸면 여기를 고친다
- 지표가 어느 키를 받아 오는지는 `Metric.src` 다(`"us.mumuki.amazon.revenue"` — 마켓·브랜드·채널·지표).
  비어 있으면 손으로 넣는 칸이다

### 시트 붙이기

이름 규칙은 **`SHEET_<마켓>_<브랜드>_<채널>`** 이다. 칸마다 시트가 따로 붙는다.

| 이름 | 값 |
|---|---|
| `SHEET_US_MUMUKI_AMAZON` | 문서 ID (주소의 `/d/` 와 `/edit` 사이) |
| `SHEET_US_MUMUKI_AMAZON_GID` | 일별 롤업 탭의 gid. 기본 `0` |
| `SHEET_US_MUMUKI_D2C` · `_GID` | 무무키 자사몰 시트가 생기면 |
| `SHEET_US_PETHROOM_AMAZON` · `_GID` | 페스룸 아마존 시트가 생기면 |
| `SHEET_CA_MUMUKI_AMAZON` 등 | 캐나다를 열면 같은 규칙으로 |
| `FEED_REVALIDATE_SECONDS` | 다시 읽는 주기(초). 기본 300 |

**넣지 않은 칸은 그냥 수기 줄로 남는다.** 지금은 `무무키 · US · 아마존` 하나만 붙어 있다.

## 데이터가 사는 곳

```
브라우저  ──GET /api/board──▶  lib/store.ts  ──▶  Redis (Upstash REST)
        ◀─────state, rev──┘                       키 하나: kpi-board
        ──PUT /api/board──▶  rev 검사 → rev+1 → 저장
```

보드 전체가 **JSON 한 덩어리**다. 팀원 몇 명 · 프로젝트 몇 개 · 업무 몇백 줄이면 이 방식이 제일 단순하다.
업무가 수천 줄로 늘어나면 그때 테이블로 쪼개는 게 맞다.

**동시 저장은 마지막이 이기지 않는다.** 저장할 때 자기가 읽었던 `rev` 를 같이 보내고, 그 사이 누가 먼저
저장했으면 409 로 거절한다. 화면에는 "다른 사람이 먼저 저장했습니다" 가 뜨고, 저장된 내용을 불러온 뒤
다시 고치게 된다.

**내 저장이 날아가 있는 동안에는 두 번째 저장을 띄우지 않는다.** `rev` 는 응답이 와야 오르는데 그 전에
또 보내면 낡은 번호로 가서 자기가 자기한테 409 를 받는다. 그때 화면에는 있지도 않은 "다른 사람" 이
뜬다 — 그래서 저장 중에 생긴 변경은 응답을 받은 뒤에 이어서 보낸다.

다른 사람이 바꾼 건 **20초마다** 가져온다. 내 쪽에 저장 안 된 변경이 있으면 건드리지 않는다.

## 최초 설정

### 1. Vercel 프로젝트 만들기

이 폴더를 깃 저장소로 올리고 Vercel 에서 import 한다. 빌드 설정은 기본값 그대로면 된다.

### 2. Redis 붙이기

Vercel 프로젝트 → **Storage** → Redis 생성 후 프로젝트에 연결. 연결하면 아래 두 값이 환경변수로
자동 주입된다.

| 이름 | 설명 |
|---|---|
| `KV_REST_API_URL` | Redis REST 주소 |
| `KV_REST_API_TOKEN` | Redis REST 토큰 |

**이게 없으면 배포본은 화면에 설정 안내를 띄우고 멈춘다.** 파일에 쓰는 로컬 방식으로 조용히 넘어가지
않는다 — 그러면 저장한 것처럼 보이다가 다음 요청에서 사라지기 때문이다(Vercel 은 실행 중
파일시스템이 읽기 전용이다).

확장 진행판과 **같은 Redis 를 써도 된다.** 키 이름이 `expansion-board` / `kpi-board` 로 다르다.

### 3. 편집 키 (선택이지만 권장)

| 이름 | 값 |
|---|---|
| `BOARD_WRITE_KEY` | 팀에서 공유할 문자열 하나 |

넣으면 **읽기는 누구나, 쓰기는 이 키를 아는 사람만** 이 된다. 팀원은 우상단 `편집 잠금 해제` 를 눌러
키를 한 번 넣고, 그 브라우저에 남는다(`localStorage`, 서버로는 헤더로만 간다).

공용 키라서 **누가 바꿨는지는 남지 않는다.** 이 보드는 사람 이름이 붙는 화면이라 확장 진행판보다
그 필요가 크다. 필요해지면 Auth.js + Google 프로바이더에 `@bmsmile.ai` 도메인 제한을 붙이는 쪽으로
간다 — 매출 대시보드에 로그인을 붙일 때 같이 하는 게 낫다.

## 보드 쓰는 법

### 월 목표

**브랜드 탭 → 마켓 탭 → 채널 줄** 세 단계다.

```
무무키 | 페스룸          ← 브랜드 탭
  US | CA                ← 마켓 탭 (지금은 US 하나)
● 아마존   [총매출][총 ROAS][내부 광고비][외부 광고비]
● 자사몰   [총매출][총 ROAS][내부 광고비][외부 광고비]
```

지표 하나는 **브랜드 × 마켓 × 채널** 한 칸에 산다. 화면에는 늘 2줄 8칸만 떠서, 브랜드와 나라가
늘어도 한 장의 밀도가 그대로다. 두 채널이 같은 지표를 같은 순서로 들고 있어서 아마존과 자사몰을
위아래로 바로 견줄 수 있다. 기본 네 칸은

| 지표 | 단위 | 방향 |
|---|---|---|
| 총매출 | USD | 많을수록 좋음 |
| 총 ROAS | 배 | 많을수록 좋음 |
| 내부 광고비 | USD · 목표 없음 (TACoS 자동 계산) | — |
| 외부 광고비 | USD · 목표 없음 (TACoS 자동 계산) | — |

- **왼쪽 큰 숫자가 실적, 오른쪽이 목표.** 목표는 언제나 손으로 넣는다.
  실적은 시트가 붙은 브랜드면 시트에서 오고(점선 밑줄 · 못 고침), 아니면 그 자리에서 고친다
- **달을 넘기면** 그 달은 비어 있고, `지난달 목표 구성 가져오기` 가 뜬다.
  지표 이름과 목표만 넘어오고 **실적은 빈 칸으로 시작한다**
- **막대 위의 세로 눈금은 '오늘까지 왔어야 할 자리'** 다(이번 달, 쌓이는 지표에만 나온다).
  9월 3일의 10% 와 9월 28일의 10% 는 다른 이야기라서, 색도 이 눈금을 기준으로 정한다
  - 파랑 = 눈금보다 앞 · 주황 = 조금 뒤 · 빨강 = 10%p 이상 뒤 · 초록 = 목표 달성
  - 다음 달은 아직 아무 말도 하지 않는다(파랑)
- **ROAS 처럼 쌓이지 않는 지표에는 눈금이 없다.** 9월 4일의 ROAS 3.1 은 "13% 밖에 못 왔다" 가
  아니라 지금 시점의 값 그 자체다. 그래서 목표 대비 얼마나 가까운지만 본다.
  쌓이는 지표(USD · 건)와 비율 지표(% · 배)는 **단위로 갈린다**
- **광고비처럼 적을수록 좋은 지표**는 `↓` 가 붙고 색이 반대로 간다. 100% 는 달성이 아니라
  '예산 다 씀' 이고, 이 시점 기대보다 빨리 쓰면 주황, 넘기면 빨강이다.
  `지표 편집` 에서 `↑`/`↓` 버튼으로 뒤집는다
- **광고비 두 칸에는 목표를 넣지 않는다.** 쓴 금액과 그게 매출의 몇 %인지만 보여 준다 —
  `2,508 USD / TACoS 10.1%` 한 줄로 읽힌다. 목표 칸도 막대도 푸터도 없다.
  `TACoS = 광고비 ÷ 총매출` 로 같은 줄의 매출 실적에서 자동으로 나온다.
  **내부와 외부를 더하면 그 채널의 총 TACoS** 다 — 9.7% + 1.7% = 11.4%
- **ACoS 칸은 없다.** ACoS = 광고비 ÷ **광고매출** 인데 시트에 광고매출 열이 없어서 계산이 안 나온다.
  넣는다면 시트에 `AMZ 광고매출($)` 열을 붙이거나 Helium 10 광고 데이터에서 매달 가져와야 한다.
  `총 ROAS` 와 `TACoS` 는 **총매출** 기준이라 시트만으로 계산된다
- **목표 없이 비율만 보여 주는 칸은 `basisKey` 가 걸린 칸이다.** 시드에만 있고
  (`lib/seed.ts` 의 `BRAND_METRICS`), 화면에서 새로 만든 지표는 늘 목표를 받는 보통 칸이 된다.
  기준(매출)이 0 이면 비율을 만들 수 없어 `—` 로 뜬다
- **지표를 늘리거나 이름·단위를 바꾸려면** `지표 편집`. 단위는 USD · % · 건 · 배 넷이다.
  ROAS 를 350% 로 쓰고 싶으면 단위만 % 로 바꾸면 된다
- 지표 구성은 **그 달에만 적용된다.** 9월에서 지운 지표가 10월에서 사라지지는 않는다
- **브랜드 × 마켓 칸이 비어 있으면** 그렇다고 나오고, `기본 지표 만들기` 로 채널 두 줄을 깐다.
  이미 있는 줄은 건드리지 않는다 — 다른 칸의 지표가 지워지는 일은 없다
- 지표는 **자기 칸에서만** 보인다. 무무키 US 에서 지운 지표가 페스룸이나 캐나다에 영향을 주지 않는다
- **자사몰은 아마존과 지표 이름이 같이 깔린다.** `내부 광고비` 는 아마존 PPC 개념이라 자사몰에는
  안 맞는다 — `지표 편집` 에서 이름을 고치거나 그 칸을 지우면 된다

### 프로젝트

- **왼쪽 상태 칸을 누르면** `시작 전 → 진행 → 완료` 로 돈다
- **브랜드 칩으로 분류한다.** 업무 표와 같은 규칙 — 여러 개 켜도 되고 안 켜도 된다(브랜드를 안
  가리는 팀 프로젝트). 제목 옆 드롭다운에서 브랜드를 고르면 그 브랜드 프로젝트만 남고,
  `태그 없음` 으로 아직 분류 안 된 것만 볼 수 있다
- **브랜드로 좁혀 둔 상태에서 `＋ 프로젝트` 를 누르면 그 브랜드로 태그돼서 만들어진다.**
  안 그러면 방금 만든 줄이 필터에 걸려 화면에 없고, 버튼이 안 먹는 것처럼 보인다
  (업무 표가 담당자·프로젝트를 물려주는 것과 같은 규칙)
- **오른쪽 진행률(3/7)은 이 프로젝트에 걸린 업무**에서 센다. 누르면 아래 업무 표가 그 프로젝트만 남는다
- 프로젝트 브랜드 필터와 업무 표 필터는 **따로 돈다.** 프로젝트를 무무키로 좁혀 놓아도 아래 업무
  표는 그대로다 — 업무를 좁히는 건 프로젝트 줄의 진행률을 누르는 쪽이다
- 프로젝트를 지워도 **업무는 남는다** — `상시` 로 돌아간다

### 팀원

사람마다 칸이 하나고, **지금 진행 중인 업무 두 건**과 남은 건수·지연이 적힌다.
적는 자리가 아니라 **읽는 자리**다 — 이름·역할은 `lib/seed.ts` 에서 오고 숫자와 업무는 전부 업무
목록에서 센다. 그래서 업무 표와 어긋날 일이 없다.

- **칸을 누르면 아래 업무 표가 그 사람 것만 남는다.** 업무 섹션 제목 옆 드롭다운과 **같은 상태**라
  어느 쪽으로 골라도 나머지가 따라 바뀐다. 다시 누르면 전체로 돌아온다
- 진행 중인 게 없으면 **다음에 할 것(시작 전)** 을 대신 보여 준다. 빈 칸보다 읽을 거리가 있다
- **미배정 칸은 배정 안 된 업무가 있을 때만 뜬다.** 사람은 아니지만 붙잡는 사람이 없다는 뜻이라
  같은 줄에 둔다
- 오른쪽 아래 `1/3 · 프로젝트 2` 는 **완료/전체 업무**와 그 사람이 맡은 **안 끝난 프로젝트 수**다
- **여기서 배정을 바꾸지는 못한다.** 담당자 바꾸기는 업무 표의 담당 드롭다운이 맡는다 —
  한 가지 일을 두 군데서 하게 만들지 않는다

### 주간

한 주가 한 줄이고, 펼치면 **팀원마다 자기 줄**이 있다. 적는 것은 **항목 하나씩**이라
한 사람이 한 주에 여러 개를 적고, **컨펌도 하나씩 따로** 된다.

```
▾ 9/7–9/13 이번 주   업무 4건·완료 1 지연 2   [임영유 1][이호준 1]   컨펌 대기 1
    오유찬     9월 목표 재조정 · 팀 리뷰                              ×   ＋
    임영유     신규 ASIN 리스팅 초안 3종 완료                        ×
               2종은 이미지 대기                                      ×   ＋
    컨펌 요청  무무키 자사몰 번들 가격 확정 필요             [미완료]  ×
               페스룸 9월 쿠폰 20% 승인 요청                [완료 9/8] ×   ＋
```

- 주차는 **월요일 시작**이고, 보고 있는 달에 걸치는 주가 전부 나온다. 달 첫날이 목요일이면
  그 주는 앞 달에서 시작하지만 이 달 일을 담고 있으므로 포함한다
- **주차 번호(1주차·2주차)를 세지 않는다** — 그 주 월요일 날짜가 곧 id 다. 연말에 주차 번호가
  꼬이는 문제를 처음부터 안 만든다
- **완료/미완료 토글은 `컨펌 요청` 줄에만 있다.** 컨펌하는 사람은 팀장 한 명이라, 팀원이 적은
  진행 내용마다 토글을 두면 아무도 안 누르는 버튼이 스무 개 생긴다.
  누르면 `완료` 로 바뀌고 **그날 날짜가 박힌다** — 언제 봤는지가 같이 남게(`doneAt`)
- **`＋` 는 그 사람 줄에 항목을 하나 더 만든다.** 글을 다 지우면 그 항목은 사라진다
- 맨 아래 **컨펌 요청** 은 사람에게 안 붙는 줄이다 — 팀장이 결정해 줘야 하는 것들이 여기 쌓인다.
  비어 있으면 물러나 있고, 마우스를 올리면 살아난다
- **항목 하나만 고쳐서 저장한다.** 주를 통째로 보내지 않는다 — 그 사이 다른 사람이 적은 줄이
  지워지지 않게
- **이번 주만 펼쳐져 있고 나머지는 접힌다.** 다섯 주 × 다섯 명이면 줄이 스물다섯 개라 다 펼치면
  읽을 수가 없다. 접힌 줄에는 **내가 봐야 할 것이 남았는지**만 뜬다 —
  `컨펌 대기 2`(주황) → `컨펌 완료`(초록) → 요청이 없으면 `적은 것 6`
- **팀 전체로 볼 때는 그 주에 붙어 있는 사람이 칩으로 뜬다** — `임영유 1` `이호준 2`. 칩을 누르면
  그 사람으로 좁혀진다
- **팀원을 고르면 이 섹션 전체가 그 사람 기준이 된다.** 제목 옆에 `임영유 기준` 이 붙고, 건수도
  그 사람 것이고, 사람 칩이 있던 자리에 **그 주에 그 사람이 맡은 업무 이름**이 뜨고,
  적는 줄도 그 사람 것(＋ 컨펌 요청)만 남는다. 펼침 상태는 그대로다 — 지난 주를 보려면 그 줄을 누른다
- 칩·팀원 칸·업무 표 드롭다운은 **모두 같은 상태**다. 어디서 골라도 나머지가 따라 바뀐다
- **날짜를 누르면 아래 업무 표가 그 주 것만 남는다.** 프로젝트 줄을 누르는 것과 같은 문법이다.
  좁혀 둔 상태에서 `＋ 업무` 를 누르면 **그 주 안에 기한이 잡혀서** 만들어진다
- **기한이 없는 업무는 어느 주에도 안 잡힌다.** 주간에서 세지도, 좁혀 볼 때 보이지도 않는다
- **아무 항목도 없는 주는 저장되지 않는다.** 화면에는 빈 줄로 그려지고, 한 줄이 적히는 순간
  생긴다. 다 지우면 다시 없어진다 — 빈 줄이 열두 개씩 쌓이지 않게

### 업무

- **제목 옆 드롭다운에서 담당자를 고르면** 그 사람 업무만 남는다. `미배정` 도 한 칸이다.
  좁혀 둔 상태에서 `＋ 업무` 를 누르면 **그 사람 · 그 프로젝트로 바로 배정된다**
- **기한이 지났는데 완료가 아니면** 날짜가 빨갛게 되고, 팀원 칸과 주간 줄에 `지연 2` 가 붙는다.
  담당자가 없는 업무는 `미배정` 에 잡힌다
- **브랜드는 업무 이름 옆에서 칩을 눌러 켜고 끈다.** 무무키 · 페스룸 둘 다 켤 수 있고, 안 켜도 된다
  (브랜드를 안 가리는 팀 업무). select 대신 칩인 이유는 여러 개를 고를 수 있어야 해서다 —
  표 안에서 `select multiple` 은 높이가 튀고 열지 않으면 뭐가 켜져 있는지 안 보인다.
  **채널(아마존 · 자사몰) 칩은 없다** — 월 목표의 줄 축이고 업무 태그는 아니다
- **URL 은 메모 옆 칸**이다. 리스팅·시트·광고 콘솔처럼 그 업무를 열려면 가야 하는 곳 하나.
  `https://` 없이 `docs.google.com/…` 만 적어도 되고, 열 때 붙여 준다.
  주소를 적으면 오른쪽에 `↗` 가 생기고 새 탭으로 연다 — 칸 자체는 고치는 자리라 클릭해도 안 열린다.
  `javascript:` 같은 스킴은 저장할 때 떨군다(남이 적은 주소를 다른 팀원이 누르는 칸이라서)
- 완료된 업무는 기본으로 감춘다. `완료 포함` 을 켜면 보인다

## 알아둘 것

- **저장은 눌렀을 때가 아니라 잠깐 뒤에 일어난다.** 상태 클릭은 0.4초, 글자·숫자는 손을 멈추고
  0.8초 뒤에 모아서 보낸다. 우상단 알약이 `저장 중… → 저장됨` 을 보여 준다
- **글자 칸은 blur 만 믿지 않는다.** 치다가 탭을 닫아도 0.8초 전까지 친 것은 올라간다
- **기한 비교는 브라우저 시간 기준**이다. 시차가 있는 팀원끼리 하루 차이로 다르게 보일 수 있다
- **첫 렌더에는 지연 표시가 없다.** 서버(UTC)와 브라우저(KST)가 다른 날짜로 그리면 화면이 어긋나기
  때문에, 오늘 날짜는 브라우저에서 붙은 뒤에 계산한다
- **캐나다를 열려면** `MARKETS` 에 한 줄(`{ id: "ca", code: "CA", name: "캐나다" }`)을 넣으면
  탭이 생긴다. 시트를 붙일 때만 `SHEET_CA_MUMUKI_AMAZON` 을 추가한다
- **월 지표의 기본값은 `lib/seed.ts` 의 `BRAND_METRICS`** 다. 브랜드 × 마켓 칸마다 채널별로
  이 다섯 칸이 깔린다.
  이미 만들어진 달에는 영향이 없다. 기본값은 그 달이 처음 만들어질 때만 쓰인다
- **팀원 순서와 직급은 저장된 JSON 이 주인이다.** 화면(팀원 칸 · 담당자 드롭다운 · 주간 줄)은
  `members` 배열 순서를 그대로 따르고, 이름 옆 작은 글자는 `role`(팀장 · 파트장 · 사원)이다.
  `lib/seed.ts` 의 `SEED_MEMBERS` 를 고쳐도 **이미 돌아가는 보드는 안 바뀐다** — 그 값은 보드가
  처음 세워질 때만 쓰인다. 순서를 바꿀 때는 **id 를 그대로 두고 배열만 다시 늘어놓으면** 된다.
  업무·주간·프로젝트가 참조하는 건 id 라서 배정이 흐트러지지 않는다
- **팀원 목록은 화면에서 못 고친다.** 팀원 카드를 걷어내면서 이름·역할을 고치고 사람을 넣고 빼는
  자리도 같이 없어졌다. 지금은 `lib/seed.ts` 의 `SEED_MEMBERS` 가 전부인데, **그 값은 보드가 처음
  세워질 때 한 번만 쓰인다** — 이미 돌아가는 보드에 사람을 넣으려면 코드가 아니라 저장된 JSON 을
  고쳐야 한다. 사람이 들고 날 일이 생기면 업무 섹션에 작은 `팀원 편집` 을 다시 붙이는 게 맞다.
  (`role` 과 `focus` 는 데이터에 그대로 남아 있다. 카드를 되살리면 적어 둔 것도 같이 돌아온다)
- **세 축 모두 `lib/types.ts` 의 배열이 유일한 출처다** — `BRANDS`(탭 1단) · `MARKETS`(탭 2단) ·
  `CHANNELS`(줄). 한 줄 넣으면 탭이나 줄이 생기고, 그 칸의 지표는 `기본 지표 만들기` 로 깐다.
  브랜드를 넣을 때는 `app/globals.css` 의 `.bchip[data-b="…"]` 와 `.mtabs button[data-b="…"]` 에
  색을 주고(밝은 쪽 · 어두운 쪽), 채널을 넣을 때는 `.mrow[data-ch="…"]` 에 준다.
  상태색(초록·주황·빨강)과 겹치지 않는 계열에서 고른다
- **`BRANDS` 는 업무·프로젝트 태그도 같이 정한다.** 그래서 브랜드를 빼면 그 태그는 다음 저장 때
  조용히 사라진다. 채널은 태그가 아니다 — 업무에 `자사몰` 칩은 없다.
  필요해지면 채널 칩을 따로 붙이는 게 맞다
- **모르는 브랜드·마켓·채널에 붙어 있던 지표는 첫 항목으로 끌려온다**(무무키 · 미국 · 아마존).
  사라지지는 않지만 남의 칸에 섞이니, 목록에서 뭔가를 빼기 전에 그 칸의 지표를 먼저 지우는 게 낫다
- **프로젝트·업무는 코드에 없다.** 전부 화면에서 만든다. 확장 진행판의 브랜드·국가처럼 코드가
  목록의 주인인 구조가 아니다
- **주차 줄도 코드에 없고 저장에도 없다.** 화면이 달력에서 만들어 그린다(`weeksOfMonth`).
  저장에 남는 건 뭔가 적힌 주뿐이고, 팀원이 지워지면 그 사람이 찍은 확인 표시는 풀린다 —
  없는 사람이 확인한 것으로 남지 않게
